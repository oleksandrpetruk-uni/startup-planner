## 2. Хід виконання роботи

### 2.1. Налаштування безперервної інтеграції (CI)
Для автоматизації тестування у репозиторії проєкту було оновлено конфігураційний файл `.github/workflows/tests.yml`. Під час налаштування було усунено проблему запуску модульних тестів: виправлено синтаксис виклику утиліти `coverage run -m unittest` шляхом видалення розширення файлу `.py`, яке викликало помилку `ModuleNotFoundError`.

Після внесення виправлень конвеєр GitHub Actions запустився автоматично та завершився успішно, підтвердивши 100% проходження тестів та стабільність розробленої логіки.

### 2.2. Проведення Code Review (Рецензування коду)
Було створено робочу гілку `review-oleksandr` та відкрито запит на злиття (Pull Request) в головну гілку `main`. У межах цього запиту було проведено інспекцію вихідного коду та залишено 5 коментарів щодо покращення архітектури та стилю коду:

1. **Магічні числа (Magic Numbers):** Числа 10 та 1000 жорстко закодовані в умові. Рекомендується винести їх у константи класу (наприклад, `MIN_TEXT_LENGTH = 10`), що зробить код гнучкішим.
2. **Типізація (Type Hinting):** Для повернення структурованого списку рядків доцільно використовувати чітку конструкцію `List[str]` із модуля `typing` замість загального `list`.
3. **Висока когнітивна складність (High Cognitive Complexity):** Послідовне використання безлічі конструкцій `if-else` та операторів `or` ускладнює сприйняття коду. Рекомендовано винести зв'язки у словник.
4. **Оптимізація виконання (Optimization):** Переведення рядка у нижній регістр виконано один раз перед початком аналізу, що запобігає повторному виклику методу `.lower()` в циклі.
5. **Захисні умови (Guard Clauses):** Замість глибокої вкладеності блоків застосовано оператор `continue` для швидкого пропуску невідповідних елементів.

Після перевірки рецензії (Submit review) Pull Request було успішно злито з основною гілкою (Merged).

## 3. Статичний аналіз коду за допомогою Radon
Для отримання об'єктивної оцінки внутрішньої якості коду модуля `startup_planner.py` було використано утиліту `radon`.

### 3.1. Цикломатична складність (Cyclomatic Complexity)
**Команда:** `radon cc startup_planner.py -a`

* Усі ключові блоки коду проєкту отримали оцінку **B** (помірна складність).
* Загальна середня цикломатична складність файлу становить **7.6**. 

Оцінка зумовлена наявністю необхідних розгалужень для бізнес-логіки (перевірки валідності, пошук ключових слів). Код залишається зрозумілим і не є перевантаженим надлишковими вкладеними циклами.
